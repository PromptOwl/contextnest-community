# How to map operations

Five phases, in order. Each narrows the input to the next, so the result is a legible map rather than a pile of pasted procedures.

1. **Classify.** From the documents, the tools in use and the job titles, name the function (revenue, people, finance, customer, IT, supply chain, or mixed) and how mature it is (ad hoc, documented, measured, optimised). If it is mixed or unclear, say so and ask a person to confirm.
2. **Ingest.** Gather the procedures, the tool list and the org shape. Remove secrets and personal data before anything is summarised (see source-and-privacy-rules).
3. **Map.** Write each recurring process as a process document: trigger, ordered steps, owner, end state. Write each handoff between teams or systems. Record who is responsible for each step.
4. **Find bottlenecks and automation.** Look for waiting, manual steps, a single owner, and procedures people rely on that nobody wrote down. Write each as a bottleneck (with severity and evidence) or an automation candidate (impact times effort). Record a missing procedure with the tag sop-gap.
5. **Review.** Everything lands as a draft. A person who owns the area approves it before agents rely on it.

Distill, never paste: if a document does not help answer one of the thesis questions, do not write it.
