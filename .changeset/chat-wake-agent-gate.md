Agents woken in the team chat can put an approve card in front of their own work, and continue when a person decides. `context_propose` (MCP) and `POST /nests/:id/threads/:threadId/propose` file the agent's plan as a draft for review under its own key and post a card in the thread; approving or rejecting it (REST or MCP, as any review) sends the agent one signed `agent.proposal.decided` wake with the thread and the decision. An agent deciding its own card wakes nothing; a hired key and its hirer share a login, so that is told apart by key: the hirer deciding wakes the agent. `AGENT_WEBHOOK_INTERNAL_HOSTS` lets the operator name internal runner hosts (e.g. `runner` on the same compose network) that an agent webhook may target; every other private address is still refused. The super admin can also edit that list under Server settings → Features → Team chat. The decision wakes an agent only when its card was filed on that agent's own hired key, or by the login that set up its webhook: a declared `client.agent` or a key label is not proof.
