Slack connect now checks the server before sending anyone to Slack, and every connect failure says how to fix it (po-1444). When `PUBLIC_BASE_URL` is unset, not `https://`, or a localhost or private address, "Open Slack to approve" refuses with a page that names the address and lists the steps, starting with Server settings → Basic → Public base URL. Before, Slack showed its own `redirect_uri did not match` page and never came back. Control room → Setup step 1 shows a checklist (Slack can reach this server, message buffer key set, model key set), each line with its fix, and the exact redirect URL the Slack app must list, with a Copy button. `GET /surfaces/status` carries a `readiness` block for server admins (booleans and the public URL only, never a secret). The OAuth callback explains Slack's own `error` (a cancelled install says so instead of "This sign-in link isn't valid"), the session-mismatch message says to finish in the same browser within 10 minutes, and the start routes' errors render as a page in the browser instead of raw JSON.
