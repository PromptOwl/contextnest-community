Team chat harness, slice C1 — what you can do to one channel message (experimental, behind the channels switch `EXPERIMENTAL_AGENT_STREAM`; server and MCP, the screens follow). React to a message with an emoji or a shortcode (`:+1:`), and see who reacted on every read. Edit a message you wrote — the earlier text is kept and any member can read it; a name the edit adds is notified, a name it removes is dropped from that person's My Work. Delete a message you wrote: it becomes a tombstone that keeps its place and its replies, and leaves My Work and search at once; a nest owner or admin can delete anyone's, recorded as moderation. Pin messages in a channel and list the pins. Save a message for later and find it under `GET /me/saved` and the new `saved` section of My Work. Every message now has a permalink `url`, and `GET /nests/:id/messages/:id` opens one by id. Search a nest's channels (`GET /nests/:id/channels/search?q=`) or every nest you belong to (`GET /me/chat/search?q=`), newest first with excerpts and highlights — the same matcher as the document search, which now also returns matching channel messages (`messages`) next to its documents; it considers the 5,000 newest messages in scope. Pins and saved items are kept in the document pin store, so they go when a person leaves a nest, exactly as document pins do. `@channel` (and, until presence exists, `@here`) puts a message in front of every other person added to the nest, bounded at 200 people, and never wakes an agent. Over MCP: `context_message_read`, `context_message` (react, unreact, edit, delete, pin, unpin, save, unsave), `context_channel_search`, `context_channels { action: "pins" }` and `context_my_work { sections: ["saved"] }` return exactly what the routes return. Everyone added to the nest can do all of this, a read-only collaborator included; the public and document-share grantees can't, and a read-only API key can only read. With the switch off none of it exists.
