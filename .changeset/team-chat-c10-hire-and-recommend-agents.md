Hire agents, and recommend them (team chat harness, C10; server and MCP, behind `EXPERIMENTAL_AGENT_STREAM`). A person on a nest can see the kinds of agent this server can offer (`GET /nests/:id/hire/catalog` — Hootie, a watcher, a webhook agent, a key agent — each in plain words with what it needs, what it may do, its cost, who may hire it and whether it is available right now), hire one in one call (`POST /nests/:id/hire`), see who is hired with a status (`GET /nests/:id/hire`), and let one go (`DELETE /nests/:id/hire/:kind/:handle`). Hiring creates the existing thing underneath through its own service and gate — a per-nest Hootie row, a metacognition agent over the channels folder, an agent webhook with its one-time secret, a nest-scoped agent key returned once — and the hired list is derived from those rows. `announce: true` posts one welcome line per channel as the hiring person, never model text. Rule-based recommendations (`GET /nests/:id/agents/recommendations`, at most five, no model calls): questions nobody answered for a day, a channel that keeps turning threads into records, an @name people keep tagging that nobody answers to, a webhook that isn't getting through, a key agent silent for a month — each with evidence links and a ready hire payload, limited to what the caller can read, dismissible per person. The channel list carries `recommendations_count` for a quiet badge. MCP: `context_hire_catalog`, `context_hire_agent`, `context_hired_agents`, `context_agent_recommendations`. Migration 092 adds `hired_agents` (Hootie's per-nest row only).
