Memory snowball (team chat C6). Every conversation can now grow the nest's memory, through the review queue and attributed to a person. **Remember this** — `POST /nests/:id/threads/:threadId/remember { message_id?, kind?: "note" | "decision" | "task" | "fact", title?, summary?, folder? }` (MCP `context_remember`) — turns one message or a whole thread into a node the way the caller's own draft lands: on a governed nest a draft in the review queue requested by them, elsewhere published. The node quotes the source with names and times, records `source_thread`, and the thread gets a reply linking it; the same (thread, message, kind) twice returns the existing node. A caller declaring `client.agent` creates it under their person's login with the agent recorded as proposer; a read-only member is told to ask a writer or @mention one. **Corrections** — `POST …/threads/:threadId/correct { message_id, node_id, replacement?, note? }` (`context_correct`) — make the edit proposal a person's own edit would: a new draft version of the node with a marked "Correction from #channel (date), by name" block, submitted for review. **Thread ↔ node relations** are recorded automatically as `task:discussed-in` edges when a message links a node and when a thread is promoted, remembered, corrected or proposed from: `GET …/nodes/:id/relations` and `context_relations` gain `discussed_in`, channel posts and thread reads gain `related_nodes`, never naming a node the reader can't open. **Channel knowledge** — `GET …/channels/:name/knowledge` (`context_channel_knowledge`) lists the nodes a channel produced with their review status and open proposals; the channel list carries `knowledge_count` and `watched`. **Channel watcher** — `PUT …/channels/:name/watch { enabled, mode: "quiet" | "asks", quiet_minutes?, agent? }`, `GET`, `POST …/watch/run` (`context_channel_watch`, owner/admin) adds the nest's existing metacognition agent to a channel: after a quiet window with no new message, or on "@nest remember this", it judges a bounded batch (silent on chatter, logged why) and proposes nodes, edits and relations as drafts under review in its persona's name; it never posts in the channel, and without a model key the setting saves as inactive. **Decision ledger** — `GET /nests/:id/decisions` (`context_decisions`): every decision promoted or remembered from a thread, newest first, with who decided, when and the source thread. No migration: every store is an existing table. Channel routes and tools follow `EXPERIMENTAL_AGENT_STREAM`; remember, correct and the ledger work on document threads too, like promote.
