The nest in the conversation (team chat C7, experimental, `EXPERIMENTAL_AGENT_STREAM`). With Hootie on, `@hootie` (or `@nest`) in a channel post or reply asks the nest from inside the thread: the same Hootie turn as the panel runs as the person who asked — their retrieval, their read tools, their citations — with the thread's earlier messages as quoted, untrusted context, and the answer lands in the thread as a message from "Hootie, for <asker>", marked as model text with the citations the server verified (links in it are inert). It is attributed to the agent, never to a person, and it notifies and wakes nobody. When Hootie wants to write, it doesn't: a proposal becomes a draft authored by `hootie` in the review queue plus a card in the thread, and a reviewer approves or rejects it with the ordinary review routes; the card follows the decision. `POST /nests/:id/ask` and MCP `context_ask_nest` run the same turn on demand (posting only with `post: true`). Every agent the nest knows gets a profile — what it is, when it was last seen, what it did, what it knows (only what you can read), whether a mention wakes it — at `GET /nests/:id/agents[/:handle]` and MCP `context_agents`; an owner or admin can describe it. Handoffs between people and agents are recorded in the thread as ordinary messages that mention the target (so they land in My Work or wake the agent), with accept and done (`POST /nests/:id/threads/:threadId/handoff`, `/handoffs/:messageId/accept|done`, MCP `context_handoff`). The handles `hootie`, `nest`, `channel`, `here` and `everyone` are reserved, and the marks only the server writes into a message (`model_answer`, `proposal`, `handoff`, …) can't be forged through `client`. Migration 091 adds `agent_profiles` (the description).
