**Views can write rows back to tables, as governed drafts.** New `POST /nests/:nestId/nodes/:nodeId/rows` applies `append` / `update` / `delete`-by-`:key` row ops to a table node: typed against the header (unknown columns, non-numbers in `:number`, duplicate keys refused), all-or-nothing, minimal line edits, `base_version` → `409`. It writes through the same update path as a body edit, so it publishes on an ungoverned nest and drafts (optionally submitted for review with `submit_review: true`) on a governed one, with the caller's own permissions. A view's `html` block can opt in with a `write_to: ["<data block id>"]` layout field: its sandboxed frame (still `connect-src 'none'`) posts `{type:"nest-write", block, ops}` to the view page, which checks the sending frame, `write_to` and the caps, calls the endpoint with the viewer's session and posts `nest-write-result` back. The page carries this one hash-pinned script only when the approved layout and artifact were written by members with write access; other view pages, frames, `/p` and the public docs site are unchanged. `write_to` takes effect once the engine's view schema accepts it (proposed upstream). The review screen shows a table draft's row changes. `CN_VIEW_WRITES=off` turns write-back off.
