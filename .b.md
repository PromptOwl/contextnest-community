## What

Two fixes for agents working with a nest over MCP on behalf of a person.

**1. Agents get a link a person can open.**

- `nest_index` and `GET /index`: each nest has `web_url` (`{base}/nest/{id}`), structured and in the markdown. The markdown labels it "web (for people)" and the API URLs "for agents".
- `context_get`, `context_create`, `context_update` and a `context_upload` document: the result text carries `{base}/nest/{nestId}?doc={node id, URL-encoded}`. `context_list` and `context_search` end with the address pattern (one line, not a link per row). `nest_create` answers with the new nest's link.
- REST: `POST /nests/:id/nodes` and `PATCH /nests/:id/nodes/:nodeId` return a top-level `web_url` (the `GET` shape is unchanged).
- `/llms.txt` has a "Links for people" section, and the server-level connect instructions say the same in one line.
- Safety net: a browser page load of `/nests/<id>`, `/nests/<id>/mcp` or `/nests/<id>/context` with no `Authorization` header and no query string gets a 302 to `/nest/<id>`.

**2. HTML posted by an agent renders as a page.**

- `context_create` / `context_update` descriptions (and `/llms.txt`) say: for an HTML page use `type: "artifact"` and put the raw HTML document in `content`, with no code fence.
- Guard rail on agent writes (MCP, and REST when the request carries an API key):

| The write | Stored as | Result says |
| --- | --- | --- |
| no type or `document`; whole body is one `html` fence or a full HTML document | `artifact`, fence removed | "Stored as an HTML artifact…" + the web link |
| the same, artifacts disabled (`TYPE_ARTIFACT_ENABLED=false`) | as sent | "…artifact nodes are disabled on this server…" |
| an `artifact` (new or existing) with a fenced body | fence removed | "The code fence around the HTML was removed…" |
| markdown with text around an html block, another node type, `append`, a save from the web app | as sent | nothing |

- An artifact already stored with a fence is unwrapped when it is served (`/hosted`, `/p`).

## Why

- MCP results had no web link at all. Asked for "the link", an agent built one from the API or MCP URL. On the hosted server a browser GET of `/nests/<id>` answers `404 {"error":"Not found"}` today (checked against production), which is the dead link that was reported.
- The `context_create` schema called `content` "Markdown content body" and said nothing about HTML, so an agent asked to post a page sent a document whose whole body was one `html` code block.

The structured payloads of the catalog-bound tools (`context_get`, `context_create`, `context_update`, `context_list`, `context_search`) are unchanged: the link is in the prose, as #562 did for the last-edit line, because `test/mcp-catalog-conformance.test.ts` refuses a key the engine catalog does not declare. `nest_index` has no engine operation, so `web_url` is structured there. No new tools and no new inline schemas (`lint:mcp-schemas` stays at 103).

## Steps to test

1. Connect an MCP client to `https://<server>/mcp` and call `nest_index`. Each nest shows `- web (for people): https://<server>/nest/<id>`, and `structuredContent.nests[].web_url` has the same value. Open it in a browser where you are signed in: the nest opens.
2. On `https://<server>/nests/<id>/mcp` call `context_create` with `{ "title": "Link check", "content": "# Hi" }`. The result ends with `Open in the web app (the link for people …): https://<server>/nest/<id>?doc=nodes%2Flink-check`. Open it: the document opens.
3. Call `context_get` for that document. The header block has a `**Web link (for people):**` line with the same address.
4. Paste `https://<server>/nests/<id>` into the address bar. You land on `https://<server>/nest/<id>` (the app, or its sign-in), not JSON or a 404. Do the same with `/nests/<id>/mcp`.
5. `curl -H "Authorization: Bearer <key>" https://<server>/nests/<id>` still returns the nest JSON. `curl https://<server>/nests/<id>` (no key) returns the same answer as before this change.
6. Call `context_create` with no `type` and `content` set to a full HTML page wrapped in an `html` code fence. The result says "Stored as an HTML artifact". Open the link: the page renders, with no code block.
7. Call `context_create` with a heading, a sentence and an `html` code block as `content`. It stays a document and shows the code block.
8. Call `context_update` on the artifact from step 6 with a new fenced body. The result says the code fence was removed. Reload: the new page renders.
9. Set `TYPE_ARTIFACT_ENABLED=false`, restart, and repeat step 6 with a new title. The document is stored as sent and the result says artifact nodes are disabled on this server.
10. In the web app, create a document whose whole body is an `html` code block. It stays a document.
